Phase 2: building prompt intelligence

Visibility numbers are only as meaningful as the prompts behind them. Phase 2 builds a prompt library that reflects how buyers actually ask AI systems for help, then groups prompts so results can be read by intent instead of one prompt at a time.

Pagezii roadmap / Phase 2: Prompt intelligence

Where do realistic prompts come from?

There is no public prompt-volume data comparable to keyword search volume, so the library has to be assembled from proxies. Good sources are keyword research converted into natural questions, sales and support call notes, community threads where buyers ask for recommendations, and comparison pages competitors already rank for. Pagezii's note on what prompt intelligence is explains why questions behave differently from keywords.

Our guide on how buyers use AI search lists the question patterns B2B buyers use most, which makes a practical starting taxonomy.

How should prompts be classified?

Classify every prompt by commercial intent, because a mention in a "best tools for" answer is worth more than one in a definition. A small, fixed taxonomy beats a clever one: marketers have to recognize the labels.

How are prompts grouped automatically?

Embed every prompt, store the vectors in PostgreSQL with pgvector, and cluster them with HDBSCAN. HDBSCAN suits this job because it does not need the number of clusters in advance and leaves outliers unassigned instead of forcing them into the nearest group. OpenAI's embeddings guide covers model choice and dimensions.

pythonimport numpy as np
from openai import OpenAI
from sklearn.cluster import HDBSCAN

client = OpenAI()

def embed(texts: list[str], model: str) -> np.ndarray:
    resp = client.embeddings.create(model=model, input=texts)
    return np.array([d.embedding for d in resp.data])

def cluster_prompts(prompts: list[str], model: str) -> list[int]:
    X = embed(prompts, model)
    X = X / np.linalg.norm(X, axis=1, keepdims=True)   # cosine via unit vectors
    labels = HDBSCAN(min_cluster_size=5).fit_predict(X)
    return labels.tolist()                              # -1 = unclustered
sqlcreate extension if not exists vector;
alter table prompts add column embedding vector(1536);  -- match your model
alter table prompts add column cluster_id int;

-- Nearest prompts to a new question, for de-duplication
select id, text
from prompts
order by embedding <=> :new_embedding
limit 10;
Hint

Have a human name every cluster before it appears in a report. An automatic label like cluster 17 means nothing to a customer; a name like CRM for small sales teams does.

How do you keep the library current?

Treat the prompt library as versioned data. Add prompts in batches, re-cluster on a schedule, and never edit a prompt in place, because that silently breaks its history. Retire prompts instead and keep their runs. When a new batch lands, check it against existing prompts with a nearest-neighbour query so near-duplicates do not inflate a cluster's weight.

CTO rule

Version the prompts, not just the code.

A change in visibility is only meaningful if the prompt set stayed the same. Tag every report with the prompt library version it used.
