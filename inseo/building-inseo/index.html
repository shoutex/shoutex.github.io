Building InSEO: how we scoped and built an MVP Chrome extension

The product decisions, the simplified architecture and the UX choices behind InSEO, written for founders and teams building their own first version.

ShoutEx InSEO documentation · Updated October 2026
ShoutEx InSEO / Building InSEO

Why build InSEO as a Chrome extension?

We wanted on-page checks where the work happens: on the page itself, while you write or review it. A browser extension needs no account, no crawl and no setup. You open any page, live or in staging, and get an answer in seconds. That decided the product's shape before any code was written.

What went into the first version, and what waited?

We scoped InSEO as a minimum viable product (MVP): the smallest tool that answers one question well. The question was “is this page built for my keyphrase?” Everything that did not answer it waited.

In version 1

  • Keyphrase scoring for up to four keywords and synonyms
  • Title, meta, OG, URL and heading checks
  • Anchor text, external links and body keyword checks
  • One diagnostic score with per-check detail
  • Zero setup, runs in the browser

Moved to later

  • AI recommendations and rewrites
  • AI search readiness checks
  • Accounts, history and saved reports
  • Site-wide crawling
  • Local SEO signals

This is the same discipline we use with clients. Our guide to the MVP development process walks through how to scope, build and launch a first version without building the roadmap too early.

Which UX decisions shaped the popup?

A popup is small. Every pixel has to earn its place, so we made a few deliberate choices.

The principles behind it

  1. Keyphrase first. The keyphrase is the first input, because every score depends on it.
  2. Percentages per check. A number per row makes it obvious where to start.
  3. Show what was found. Lists of headings, links and domains let you verify the score instead of trusting it.
  4. No setup. Install, open a page, type a keyphrase. Nothing else.

What would we tell another team building an MVP tool?

Answer one question extremely well, ship it, and let real use decide what comes next. Keep a written list of what you cut, so the roadmap starts from deliberate choices rather than forgotten ideas.
